Poor

The redesign converged on what it set out to fix. Both independent reviews confirm, in a dedicated "Closed / well-pinned" section, that every headline problem from rounds 1–3 is now closed by construction, not just by restated intent: the gate-state/CI-write contradiction, the fork-PR token gap, the branch-protection deadlock, the review-dismissal-on-push issue, the local/CI write race, the trailer-grammar and spec-id-encoding gaps, and the undeclared GitHub-specific assumption are all gone because CI is now provably read-only end to end and there's no commit-trailer left to parse.

What's left is almost entirely about specifying the replacement mechanism fully — waypoint verify's "makes its own commit" line hides a bootstrapping deadlock with its own pre-commit gate (found independently by both reviews), an unspecified commit-isolation contract in runCheck(), and shallow-clone/squash-merge SHA resolution. These are narrow, independently fixable specification gaps in one new mechanism — not a new instance of the structural, comparable-severity-every-round pattern from rounds 1–3. That pattern is broken.

What's now genuinely closed by construction

  • Gate-state/CI-write contradiction (rounds 1–3's headline issue) — fully closed. .gate-state is local-only, gitignored, never expected on a fresh checkout; CI's check doesn't touch it at all.
  • Fork-PR token gap, branch-protection deadlock, review-dismissal-on-push, local/CI write race — all closed. All four depended on CI needing write/push permissions; CI is now read-only end to end.
  • Trailer-grammar and spec-id-encoding gaps — closed. No trailer left to parse; verify takes identity as explicit CLI arguments.
  • Undeclared GitHub-specific assumption — closed. CI needs no elevated permissions and works identically across providers.
  • Async execution ambiguity — closed. verify is explicitly synchronous, tradeoff justified rather than left implicit.

Critical findings (3 distinct root causes)

critical
critical

waypoint verify's own commit collides with the pre-commit gate it must pass

found independently by both reviews
The default patch-classified globs don't cover tasks/**, so a ledger-only commit is Feature-tier-classified with no spec delta — exactly what gate() blocks. As written, verify likely can't complete its own commit on any Feature/System-tier spec, breaking the mechanism the first time it's used.
Fix: Add tasks/** to the default patch bucket, or explicitly document that verify's internal commit intentionally skips hooks.
critical

runCheck() never specifies how commitSha gets materialized before checkCommand runs

Nothing says whether an implementation must isolate/checkout that commit or can run the check in-place. Skipping isolation means CI's per-task loop could end up checking every task against the same current HEAD regardless of what linked_commit says — silently defeating the redesign's central claim.
Fix: Pin runCheck() to require an isolated checkout of commitSha, or explicitly scope MVP to same-commit-only checks.
critical

Shallow CI clones and squash-merge can make a recorded linked_commit unresolvable

Default shallow checkouts mean older SHAs aren't in CI's object database; squash-merge rewrites every feature-branch commit into one new SHA on merge. The document doesn't distinguish "commit not found" from "check genuinely regressed."
Fix: State a required CI checkout depth/merge-strategy assumption, or define "commit not resolvable" as a distinct, non-failing outcome.

High findings (5)

high
high

Self-commit's staging scope is unpinned and collides with a known git gotcha

Plain `git add <ledger> && git commit` doesn't isolate the commit from other already-staged files.
Fix: Specify the verify commit must be isolated to the ledger path alone (`git commit --only`).
high

Re-running waypoint verify on an already-done task is undefined

v0.3 had an explicit idempotency rule; v0.4 removed the subsystem that rule lived in with no replacement.
Fix: State whether a re-verify no-ops, errors, or re-verifies-and-overwrites.
high

Bypass-logging guarantee is conditional on branch-protection/PR infrastructure never stated as a precondition

A solo developer pushing straight to main (brief.md's own stated primary user) with no PR leaves zero record anywhere if they bypass locally.
Fix: State the precondition explicitly, or keep a minimal local fallback log for the no-PR case.
high

CI's "done-claim correctness" re-check has no bound and no dedup strategy

Re-running a full check_command once per done task with no caching could mean hundreds of test-suite runs per PR as a repo accumulates tasks.
Fix: Scope the re-check to specs touched by the PR, and/or dedup by unique linked_commit.
